### 1. 用一分钟介绍项目？

我用 Goodreads 诗歌真实评论构建了本地可复现推荐系统，先全局时间切分，再训练集 K-Core，比较 Popularity、ItemCF 和 InfoNCE 双塔，用 FAISS 召回、DeepFM 精排并通过 FastAPI 展示。项目同时保存真实指标、消融、环境和测试，性能结论以报告表格为准。

### 2. 为什么选 Goodreads 诗歌？

它保留图书业务和评论时间，官方子集规模适合 CPU 实验。代价是体裁单一、用户有选择偏差，不能代表整个图书平台。

### 3. 为什么不用 goodbooks-10k？

当前 Goodreads 子集可获取且有 date_added，满足真实时间切分要求。不能给缺少时间戳的交互凭空生成日期再称为 temporal 实验。

### 4. 正反馈如何定义？

去重后评分至少 4。它表示正向评分代理，不是点击或阅读完成；0 分和低评分不直接当作可靠曝光负例。

### 5. 时间字段可靠到什么程度？

date_added 是记录添加时间，不保证读完时间。报告承认这一语义限制，不把它解释成真实行为链路的所有时间。

### 6. 为何先切分再 K-Core？

全量 K-Core 会利用未来活跃度决定训练样本是否保留。训练内迭代筛选更接近当时可用的信息，但仍导致主指标偏向活跃人群。

### 7. K-Core 为什么迭代？

删除低度书籍会让部分用户也低于阈值，反之亦然。必须迭代到固定点；测试包含会导致级联删除的例子。

### 8. ID Mapping 为什么只在训练拟合？

保证模型目录仅含当时可训练实体，避免给未来 ID 虚设训练表示。验证/测试未知实体统计后排除主 warm 指标，新用户在服务中热门兜底。

### 9. 为什么不用随机切分？

随机切分可能用未来偏好预测过去，尤其对时间漂移敏感。当前全局边界确保所有训练时间早于验证和测试，代价是冷启动比例较高。

### 10. 如何防止重复交互泄漏？

先按 UTC 时间排序，每用户书籍 pair 只保留最早记录，再切分。测试验证三段 pair 不相交，但这也意味着不建模重复消费。

### 11. 热门推荐有什么价值？

它提供强且可解释的最小基线，也是新用户兜底。只有深度网络无法超过它时，应坦诚分析信号不足，而非隐藏基线。

### 12. ItemCF 相似度是什么？

二值交互列的余弦相似度：共现人数除以两本书交互人数乘积的平方根。对角线为零，用户对候选分数是历史书相似度之和。

### 13. ItemCF 为什么可能胜过双塔？

小数据下直接共现有强归纳偏置，ID 神经模型可能欠训练、过拟合或无法学到足够结构。本项目不会预设复杂模型必须更好。

### 14. ItemCF 扩展瓶颈是什么？

当前 I×I 稠密相似矩阵是 O(I²) 内存。生产可用分块稀疏乘法、最小共现阈值、每书 top neighbors 截断。

### 15. 双塔与矩阵分解有何不同？

都可用内积，但这里每侧 embedding 后还有独立两层 MLP 和归一化。当前仍只有 ID 特征，因此不能宣称有内容语义泛化。

### 16. 为什么 L2 归一化？

让内积直接对应余弦，减少向量模长对排序的影响并统一索引距离。归一化不代表推荐分数已经校准为概率。

### 17. InfoNCE 在这里如何实现？

每批 B 个正 pair 产生 B×B 相似度矩阵，对角线是标签。除已知正例外的其他列作为批内负例，温度缩放后用交叉熵。

### 18. 温度有什么作用？

控制 softmax 尖锐程度和梯度尺度。过小可能过度关注难例及噪声，过大区分不足；本次固定 0.1，没有声称做过温度搜索。

### 19. 批内负例有什么好处和风险？

共享矩阵乘法效率高，不需要额外编码负物品。风险是同物品重复、其他正例误当负例，以及出现频率受热门物品影响。

### 20. 怎样处理假负例？

主双塔屏蔽用户全部训练正例在非对角位置出现的列，保留对角标签。未来正例不可提前屏蔽，未屏蔽版本提供真实消融。

### 21. 重复 item 出现在 batch 会怎样？

相同 item 对某用户属于已知正例，非对角重复列被屏蔽。否则模型会被迫把同一向量同时当正负标签，形成冲突。

### 22. 做了 log-Q 校正吗？

没有。当前明确保留批内采样频率偏置，可后续以训练 item 频率估计 Q 并对照，但不能报告未执行的改善。

### 23. 为什么不读取测试正例排除训练负例？

这会让训练获得未来偏好信息。当前训练只排除训练正例，接受未来正例可能被误采，作为真实隐反馈局限。

### 24. 精排负例如何采样？

每训练正例从训练目录未出现的用户物品集合均匀采最多 4 个，单次无放回，跨正例允许重复。固定 seed 生成一次并保存。

### 25. 均匀负例有何不足？

通常较容易，与线上召回候选分布不同。下一步用训练内 out-of-fold 召回候选产生难负例，并保留部分随机负例防止过窄。

### 26. DeepFM 有哪些字段？

用户 ID、书籍 ID、训练热门度的 10 桶。没有使用未来总评分、标题文本或虚构用户属性。

### 27. FM 二阶项如何高效计算？

用一半的“embedding 和的平方减平方的和”，对维度求和，等价于全部字段对的内积。复杂度 O(Fd)，避免显式 O(F²d) 枚举。

### 28. 为什么叫共享 embedding？

FM 二阶项与 DNN 输入使用同一组字段 embedding 参数，因此两个损失路径共同更新它们；一阶权重另有表。

### 29. FM 与 DNN 各负责什么？

FM 显式建模字段两两交互，DNN 从拼接向量学习更复杂组合。实际有无收益要看 FM_no_deep 消融，不能仅靠结构推断。

### 30. 为什么 BCEWithLogitsLoss？

把 sigmoid 和交叉熵合并进行稳定计算，避免大 logit 直接求指数或 log(0)。评估阶段才显式 sigmoid 输出分数。

### 31. AUC 高为什么 Recall 低？

AUC 当前基于均匀采样负例，区分正例与随机书可能容易；全目录 topK 和召回候选内排序更难，且召回漏掉的正例无法被精排找回。

### 32. AUC 能表示 CTR 吗？

不能。AUC 衡量正负 pair 排序，与真实点击率不是同一概念；这里标签也是评分代理，分布还是人工负采样。

### 33. LogLoss 受负采样比例影响吗？

会。训练 1:4、评估约 1:99 形成先验偏移，输出概率不自然校准；应在真实曝光集上校准并评估，当前仅报告协议内数值。

### 34. Recall 与 HitRate 有何区别？

多正例时 Recall 是命中数除以正例数，HitRate 只关心是否命中过至少一本。当前每用户每段可以有多个正例，不能互换。

### 35. NDCG 为什么适合推荐？

它对前排命中给予更高权重，并用该用户理想排序归一化。当前二值相关性来自高评分，不使用 4 与 5 的不同增益。

### 36. 如何平均用户指标？

先逐用户计算，再等权平均，避免活跃用户主导排名结果。分类 AUC/LogLoss 则是 pair 级，这两类加权口径在报告中区分。

### 37. 为什么主指标只看 warm 用户物品？

ID 模型只能评估训练可表示实体。必须同时披露过滤人数和交互量，不能把这个子集指标冒充全量业务效果。

### 38. 测试时加入验证历史了吗？

没有，所有方法冻结在训练截止点，测试只过滤训练历史。该口径便于同条件比较，但不同于上线系统不断吸收新行为。

### 39. checkpoint 怎样选择？

双塔用验证 NDCG@20 最大值，精排用验证 LogLoss 最小值。跑满 epoch 后恢复最佳参数，测试不参与选择。

### 40. 训练 Loss 下降代表效果改善吗？

不一定。训练目标、采样分布和最终排名指标不同，还可能过拟合；必须观察验证集并按预定指标选模。

### 41. FAISS 用的 ANN 吗？

当前 IndexFlatIP 是精确全扫描。它适合小目录并作为未来 ANN 的真值基线，不应为了简历好看把它说成近似检索。

### 42. 为什么 FAISS 内积等于余弦？

用户和物品向量已 L2 归一化。没有归一化时内积会受模长影响；测试比较 FAISS 分数和 NumPy 内积结果。

### 43. 过滤已读为什么要多取候选？

直接取 K 再过滤可能不足 K。当前取 min(目录大小,100+历史长度)，过滤后保留 100 供精排，避免历史占候选名额。

### 44. 精排的召回上限是什么？

进入候选集合的真实正例比例，即候选 Recall@100。精排只能调整候选顺序，无法恢复不在集合中的书。

### 45. 如何避免线上线下不一致？

服务加载同批 mapping、训练热门桶、向量、索引与 checkpoint，使用相同过滤口径。生产还需版本清单和原子切换，当前本地固定文件演示。

### 46. 新用户如何处理？

超出训练用户范围的非负 ID 返回热门书。下一步可让用户选书或作者建立初始画像，但当前没有实现这个交互。

### 47. 新书如何处理？

目前未知书不在训练目录，因此未解决新书冷启动。内容塔、作者/体裁特征和探索配额是后续方向，需要独立冷书评估。

### 48. 怎么看热门偏置？

报告目录覆盖率、推荐书平均训练热度和热门集中度，并与基线比较。单看 Recall 容易只奖励热门书，应增加头尾分层和新颖性分析。

### 49. 覆盖率等于多样性吗？

不等于。覆盖率是全用户推荐过的不同书占比，列表多样性还需看单列表内作者、体裁或向量相似度；本项目没有伪报语义多样性。

### 50. 如何做 MMR 重排？

逐次选择相关性高且与已选结果最大相似度低的候选，用 λ 平衡两者。需要验证 NDCG 与多样性的取舍，当前只是设计方向。

### 51. 延迟数据包括哪些部分？

summary 的时间包含串行暖查询候选检索、特征张量和精排前向，不含 HTTP 网络与渲染。不能据此承诺公网 P95 或并发 QPS。

### 52. 多进程是否总能提速？

不一定，每个 worker 可能复制模型并启动多个计算线程，造成内存与 CPU 争用。应联合控制 worker 和 torch/FAISS 线程并用并发压测验证。

### 53. 如何验证代码正确性？

手算排名指标、K-Core 级联、负例历史排除、假负例全屏蔽、梯度有限、时间/pair 隔离、FAISS 数值一致性以及 API 冷启动与参数验证都有测试。

### 54. 如何保证复现？

固定 seed 和确定性算法，保存配置、实际库版本、源文件 SHA256、样本、checkpoint、逐轮日志和生成报告。跨平台浮点差异仍可能存在。

### 55. 这次消融能说明什么？

在相同数据、seed、训练预算和选模规则下对比已知正例屏蔽以及 DNN 路径的影响。单种子不能证明稳定因果收益，也没有全面调参公平性的保证。

### 56. 如果结果不如 baseline 怎么讲？

直接报告，并从小数据、稀疏性、ID 特征、采样偏移、优化预算分析。提出下一次可证伪实验，比把失败结果改成增长更可信。

### 57. 下一项最值得做的实验？

优先用训练内 out-of-fold 双塔候选构建混合难负例，解决精排训练/推理分布差异。与原均匀负例使用同样测试集合，并观察端到端指标而非只看 AUC。

### 58. 如何做统计检验？

多 seed 看训练波动，按用户 bootstrap 估计排名指标差值区间。不能把每条推荐位置视为独立样本，也不能把一次小幅提升称为显著。

### 59. A/B Test 怎么分桶？

按用户稳定 hash 分组，先 A/A 和 SRM 检查，预注册主指标、样本量与停止规则，逐步放量并设延迟错误护栏。本项目没有实际线上 A/B 数据。

### 60. 求职项目与生产系统差在哪里？

这里有真实离线闭环与可运行接口，但没有身份认证、实时特征、曝光归因、分布式训练、灰度部署和监控告警。应清晰区分已实现证据与后续架构设计。
